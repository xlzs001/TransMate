## 一、为什么先要一份"基线"

没有基线就没法回答"我们变好了还是变坏了"。

绝大多数团队的质量讨论最后都变成吵架，原因就一个：双方手里都没有数字，只有印象。
"这个函数太长了" —— 多长算长？"代码有点乱" —— 乱在哪一行？

这份报告的作用是**把印象换成数字，把数字换成可执行的动作**。
下面每一条都带文件名和行号，可以直接跳过去看。

## 六、已修复的问题（累计）

### 6.1 空 catch 块：12 处补上了"为什么可以吞"

空 `catch` 本身不一定是错的 —— 很多地方确实"失败了也无所谓"。
真正的问题是**没写清楚为什么无所谓**。半年后接手的人看到 `catch (_) {}`，
不敢删也不敢改，只能绕开走。

12 处空 catch 全部补上说明，并加进自动化门禁（见 6.4）。

| 位置 | 补的说明 |
| --- | --- |
| `background.js:99` | 上游报错时返回 HTML 错误页，解析失败保持 `{}`，由 `!ok` 分支统一抛出 |
| `background.js:422` | 读不到 session storage 就当没记过，它只是加速缓存 |
| `background.js:435` | 写缓存失败无所谓，下次重新试 |
| `background.js:1116` | 缓存当前联系人只为显示更快，存不进去不该中断消息处理 |
| `content.js:261` | `execCommand` 被站点拦截时，往下走 `setNativeValue` 兜底 |
| `content.js:274` | 只是移动光标，富文本元素不支持也不影响写入结果 |
| `content.js:375` `:376` | iframe / 非用户手势下会抛，属于尽力而为 |
| `content.js:401` | 剪贴板 API 需要聚焦 + 权限，失败走 textarea 兜底 |
| `content.js:422` | 还原焦点失败不影响已完成的复制 |
| `popup.js:63` | 当前页可能是 `chrome://`，URL 构造不出来 |
| `timezone.js:4101` | `Intl.DisplayNames` 在缺 ICU 数据的构建里会抛，退回 ISO 代码 |

> 行号会随重构漂移。表里的行号以 v3.9.13 为准；
> 想知道当前值，跑 `npm run metrics`，它会按文件列出全部空 catch 及其位置。

### 6.2 重复代码：13 组 → 10 组

**真正抽取掉的**（`background.js`）：
DeepL 的请求构造在"单条翻译"和"批量翻译"两处各写了一遍，包括同一条错误文案。
抽成 `deepLTargetLanguage()` 和 `deepLRequestInit()` 之后，两边不会再漂移。

**剩下的 10 组全是"默认值表"**：
`options.js:15` 与 `timezone.js:3250` 这类，是同一份设置默认值在两个文件里各写了一遍。
（v3.9.11 删掉 `watPresenceIndicator` 之后，这组雷同块少了 1 组 —— 减功能也会减重复。）

这种重复**不能靠抽函数解决** —— 两个文件跑在不同环境（设置页 vs 内容脚本），
没法共享一个 JS 模块。正确做法是**用测试把它焊住**，于是有了 6.4 的「默认值一致性」门禁。

> **一条重要结论：重复代码不可怕，没有保护的重复代码才可怕。**
> 能抽就抽；抽不掉的，就用测试锁死，让漂移在提交时就被拦下。

### 6.3 最复杂的函数：42 → 10

`timezone.js` 的 `detectSingleLanguage` 原本是**全项目最复杂的函数（复杂度 42）**。

看完它的内容会发现：那 20 多个 `if (/[\uXXXX-\uXXXX]/.test(text)) return ...` 分支里，
**一个"决策"都没有**，它们只是在查一张固定的 Unicode 码位表。
这不是逻辑，这是**伪装成代码的数据**。

改法：把表还原成数据。

```js
// 改之前：20 多个分支，复杂度 42
if (/[\u3040-\u30ff]/.test(text)) return makeDetectedLanguage("jpn", 1);
if (/[\uac00-\ud7af]/.test(text)) return makeDetectedLanguage("kor", 1);
if (/[\u4e00-\u9fff]/.test(text)) return makeDetectedLanguage("cmn", 1);
// ... 还有 20 多行

// 改之后：表 + 一个 8 行的循环
var SCRIPT_LANGUAGES = [
  [/[\u3040-\u30ff]/, () => ["jpn", 1]],
  [/[\uac00-\ud7af]/, () => ["kor", 1]],
  [/[\u4e00-\u9fff]/, () => ["cmn", 1]],
  // ...
];
function detectByScript(text) {
  for (const [pattern, pick] of SCRIPT_LANGUAGES) {
    if (!pattern.test(text)) continue;
    const picked = pick(text);
    if (picked) return picked;
  }
  return null;
}
```

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| `detectSingleLanguage` 复杂度 | 42 | **10** |
| `detectSingleLanguage` 行数 | 52 | **17** |
| 加一门语言的改动量 | 改控制流 | **加一行数据** |

**注意：改之前它一条测试都没有。**
先补了 4 组测试，再动结构。顺序反了就是"换一种方式犯错"。

### 6.6 `timezone.js:update`：复杂度 32，已掉出最复杂榜

`update()` 原本 94 行、复杂度 32，是**全项目最复杂的函数**。

拆成五个：

| 新函数 | 职责 |
| --- | --- |
| `loadActiveConfig(generation)` | 读存储、归一配置、修正快捷键；generation 不匹配返回 `null` |
| `syncChatTranslation()` | 同步聊天翻译的开关状态 |
| `detachPanel()` | 移除 DOM、清空 `activeState`、广播 `publishCurrent(null)` |
| `resolveContactFacts(header, stored)` | 算标题 / 号码 / 语言，并回写缓存 |
| `renderByPhone(root, facts, stored)` | 解析归属地并渲染 |

`update` 本身只剩编排。另外抽出一个纯函数 `resolveLanguageState()`：

```js
function resolveLanguageState(freshLanguage, cachedLanguage, savedManualCode) {
  const manualLanguage = makeManualLanguage(savedManualCode);
  const automaticLanguage = freshLanguage || cachedLanguage;
  const changed = Boolean(freshLanguage)
    && freshLanguage.confidence >= 60
    && (cachedLanguage?.iso3 !== freshLanguage.iso3
        || cachedLanguage?.confidence !== freshLanguage.confidence);
  return {
    automaticLanguage,
    manualLanguageCode: manualLanguage?.code || null,
    detectedLanguage: manualLanguage || automaticLanguage,
    shouldCache: changed
  };
}
```

抽它的理由不是"拆函数"，而是**它原来根本测不了**：逻辑埋在 `update` 里，
要测"置信度低于 60 不该写缓存"就必须构造一整个 storage + DOM 环境。
抽成纯函数之后，一条断言就能锁住：

```js
assert.equal(resolveLanguageState({ iso3: 'cmn', confidence: 55 }, null, null).shouldCache, false,
  '置信度低于 60 不该写 —— 避免把一次猜测固化下来');
```

> **判断要不要抽一个函数，标准不是"它有多长"，而是"它能不能被单独验证"。**

### 6.7 `background.js:translateChatBatch`：115 行 / 复杂度 22 → 47 行 / 8

原来是"读配置、归一输入、挑服务商、拼提示词、算输出预算、解析返回、
校验完整性、失败降级"全挤在一起。要改其中任何一步，都得先把整块读完。

拆成 7 个函数：

| 新函数 | 职责 |
| --- | --- |
| `normalizeChatBatchItems(items)` | 截断 16 条、丢空文本、补稳定 id |
| `buildChatBatchPrompt(...)` | 提示词模板 |
| `chatBatchBudget(normalized)` | 输出预算（按字符数算，不按条数） |
| `assertCompleteBatch(parsed, expectedIds)` | id 恰好一次、不许空译文 |
| `toChatResult(item, text)` | 统一结果形状 |
| `translateDeepLBatch(...)` | DeepL 专用批量路径 |
| `translateItemsIndividually(...)` | 失败后逐条重试的降级路径 |

**顺带修掉一个隐患**：原来三条出口各自内联拼一遍
`{ id, text, warnings: TLP_VERIFY.verifyTranslation(...) }`。
形状与校验逻辑散在三处，新增一条出口时**很容易漏加**。
集中到 `toChatResult` 之后只有一份实现，漏不掉。
（v3.9.13 把校验整个摘掉后，`toChatResult` 只剩"统一形状"这一个职责 ——
但职责还在，所以函数留着，只改名。）

这也让原来的回归断言失效了 —— 它数的是"`TLP_VERIFY.verifyTranslation(` 出现 7 次"。
**这个数字只反映写法，不反映正确性**：新增出口时它反而不会报警。
改成"数调用点 + 验行为"两条一起上：

```js
// 数调用点：只数调用，排除函数声明本身。
assert.equal((background.match(/(?<!function )toChatResult\(/g) || []).length, 4,
  '免费接口 / DeepL 批量 / AI 批量 / 逐条降级 四个出口都要经过 toChatResult');

// 验行为：真的跑一次批量翻译，确认返回的字段就是这两个。
assert.deepEqual(Object.keys(batch[0]).sort(), ['id', 'text'], '出口形状必须是 { id, text }');
```

> **教训：不要只断言"某个函数被调用了几次"。** 计数只反映**当前的写法**，
> 正确重构后它会误报、真回归时它会漏报。要数就只数"调用点"
> （`(?<!function )foo\(`，排除函数声明），并且必须另有一条**行为断言**兜底 ——
> 描述**不变量**（"每个出口都给出同一个形状"），而不是**当前的写法**（"一共出现 7 次"）。

### 6.8 `verify.js`：一个已被移除的重构案例（v3.9.13）

这一节原本记的是 `verify.js` 的重构：把 `extractHardFacts`（53 行 / 复杂度 17）与
`compareHardFacts`（53 行 / 复杂度 24）从"每种事实类型手写一遍几乎相同的代码"

手法本身没过时，现役代码里还有一份活的样本：`timezone.js` 的 `detectSingleLanguage`，
同样是把"伪装成代码的数据"还原成一张表，见 6.3。

> **表的边界在哪？** 只有当分支之间"只差数据"时才合并。
> 一旦发现要往表里加 `if (kind === 'xxx')` 之类的特判，就说明它不属于这张表。

### 6.9 新增「变异测试」门禁

前面几条都在说"要补测试"。但怎么知道补的测试**有用**？

覆盖率回答不了这个问题 —— 它只说明"这行被执行过"，不说明"这行改坏了会不会被发现"。
唯一能回答的办法是**变异测试**：故意把代码改坏，看测试会不会变红。

```
[抓住] 后台：批量出口绕过 toChatResult 自己拼对象
       免费接口 / DeepL 批量 / AI 批量 / 逐条降级 四个出口都要经过 toChatResult
[抓住] 弹窗：停用本站不再覆盖子域名
       父域名应当覆盖子域名
[抓住] 聊天翻译：中文原文不再被跳过（白花钱 + 重复气泡）
       zh-CN 下中文不该再送去翻译
...
10 / 10 个变异全部被抓住
```

实现要点：

- **全程进程内**。借 `regression-checks` 的源码覆盖钩子把文件换成改坏的版本，
  不起子进程、不动磁盘。整轮约 1.8 秒，所以能当门禁跑。
- **判定标准只有一条**：改坏后回归测试必须变红。不拿"错误信息里有没有某个关键字"当判定 ——
  断言输出里通常不含源码字面量，那样会把"抓住了"误判成"漏掉"。
- **锚点失效也算失败**。锚点是精确字符串，代码一改就可能对不上。
  这里放水的话，锚点会慢慢腐烂，最后整份变异测试变成空转 —— 那还不如没有。
  两条失败路径都实测过（锚点失效 / 变异存活）。

> **这道门禁防的是"测试变成摆设"。**
> 一个团队最容易发生的事不是"没有测试"，而是"有测试，但没人知道它还有没有用"。

> **锚点失效不是麻烦，是信号。** v3.9.13 移除"柜型自动归一"时，
> 那条盯着 `translationAutoNormalize: false` 的锚点立刻失效了 —— 这正是它该做的事：
> 提醒你"这条变异盯着的那段代码已经不存在了，你得判断它该不该跟着一起走"。
> 这一轮的结论就是**一起删**（20 个变异点里删掉 10 个）。遇到失效先判断，
> **不要把判定放宽**。

> **变异失去看护，同样是信号 —— 而且更隐蔽。** v3.9.13 删掉那两个功能后，
> "批量出口绕过统一收口函数"这条变异原本是靠"四条出口都遵守自动归一开关"
> 抓住的，而那条用例随功能一起被删了：**变异点还在，抓它的网却没了。**
> 所以这一版专门补了一条"四个出口给出同一个结果形状"的新用例盯它。
> **删功能时要顺着变异点反查一遍：还有谁在抓它？** 没人抓，就等于顺手拆掉了一道防线。

### 6.10 新增「质量预算」门禁

度量本身不拦人 —— 谁都不会因为"复杂度 32"被 CI 拦下。
这道门把度量变成**可执行的上限**：

| 规则 | 内容 |
| --- | --- |
| R1 | 不在名单里的函数超标 → 拦下（新代码不许开新坑） |
| R2 | 名单里的函数比记录值更差 → 拦下（已有的坑不许再挖深） |
| R3 | 名单里的函数已达标 / 已不存在 → 拦下，要求删条目 |

**R3 是关键。** 没有它，这份名单只会越来越长，最后变成"什么都可以"。
所以它同时是**重构待办清单**：改好一个，就来删一行。
v3.9.10 的三项重构各自触发了 R3，都是门禁主动要求删条目的。
v3.9.11 又触发了一次：删掉在线状态指示灯之后，`timezone.js:createRoot`
的 DOM 模板从 86 行降到 77 行，掉到 80 行的上限之内 —— 门禁立刻要求把
那条"有意保留"的豁免删掉。**豁免是有保质期的，过期了门禁会主动来收。**

v3.9.12 修的三条缺陷都只动了几个分支，没碰任何超标函数，所以那轮门禁
没有新的 R3 触发。修完顺带把三条变异点加进 6.9 的名单 —— **修 bug 只补
回归用例还不够，还要让它进变异测试**：否则下次有人把守卫改回去，
回归用例照样能红，但没人知道它已经失效了。变异测试就是那个"定期抽查
测试还有没有用"的机制。

v3.9.13 删掉的两个功能都不在超标名单里（`verify.js` 的 `compareHardFacts`
复杂度只有 1、`extractHardFacts` 是 3），所以这轮也没有 R3 触发。
**但"删代码"同样要跑一遍门禁**：删掉 `verify.js` 之后，质量预算的文件清单、
打包清单、度量清单、eslint 的跨文件全局声明都得跟着改 ——
漏一处就会表现成"某个门禁突然报找不到文件"，或者更糟：
"静态检查悄悄不再检查那个文件了"，而门禁依然全绿。
