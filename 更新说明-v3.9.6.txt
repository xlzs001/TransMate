TransMate 3.9.6 更新

本次是代码审阅后的集中修复，主要是几处会让功能直接不可用的 BUG：

1. 修复：OpenRouter、硅基流动这类会在模型名前加厂商前缀的服务，选 GPT-5 / o 系列
   推理模型时会直接报 400 无法翻译。
2. 修复：OpenAI 的 gpt-4o 等普通模型以前不发送 temperature，服务端用默认温度（通常 1.0），
   同一句话每次翻译结果都不一样。现在恢复正常。
3. 修复：服务商出错时如果返回一整页 HTML（网关 502、Cloudflare 拦截页），
   提示框会被几千字的网页源码塞满，真正的错误信息完全看不到。现在会自动截断。
4. 修复：内容被服务商的安全策略拦截时，提示是"没有返回翻译结果"，让人以为是配置问题。
   现在会明确告诉你内容被拦截了。
5. 修复：在设置页点"测试连接"后立刻切换翻译服务，按钮会永久卡在"测试中…"，
   只能刷新页面才能再点。
6. 修复：上一条还在翻译时再按三次空格，什么反应都没有；现在会提示"还在翻译中"。
7. 优化：后台设置变化时，不再让每个标签页都重新读取一遍设置。

本次不新增浏览器权限，更新后不需要重新授权。

【完整版】

一、会影响翻译能否用起来的 BUG

1. 带厂商前缀的推理模型无法使用

   OpenRouter、硅基流动等服务的模型名带厂商前缀，例如 openai/gpt-5、Qwen/Qwen3-8B。
   判断"是不是 GPT-5 / o 系列"的正则要求模型名以 gpt-5 或 o1/o3/o4 开头，
   带前缀的名字匹配不上，于是被当成普通模型，发出了它不接受的 max_tokens 和 temperature，
   服务端直接返回 400。现在会先剥掉 "厂商/" 前缀再判断。

2. gpt-4o 等普通模型丢失 temperature

   之前的判断是"只要是 OpenAI 官方服务就不发 temperature"，范围划得太宽。
   只有 GPT-5 和 o 系列不接受 temperature，gpt-4o、gpt-4.1 这些是接受的。
   漏发的结果是服务端退回默认温度（通常 1.0），同一句话每次翻译出来都不一样，
   用户会以为"翻译不稳定"。现在只有真正的推理模型才省掉 temperature。

二、提示信息不准确

3. 服务商错误页被原样塞进提示框

   网关或 Cloudflare 出错时经常直接返回一整页 HTML。实测最长一次是 6332 个字符，
   整个提示框全是网页源码，真正的错误信息被淹没，弹窗也会被撑破。
   现在统一压平空白并截断到 300 字符，并在末尾标注"已截断，原始响应共 N 字符"。

4. 安全策略拦截被误报成"没有返回翻译结果"

   Gemini 的 SAFETY、Anthropic 的 refusal、OpenAI 的 content_filter 等都会让服务商
   返回空内容。以前只判断"结果为空"，于是提示"XX 没有返回翻译结果"，
   用户会以为是 Key 或模型配置错了，反复检查配置。
   现在会明确提示"服务商判定这段内容触发了安全策略，拒绝翻译"。

三、界面卡死与无反馈

5. "测试连接"按钮永久卡死

   恢复按钮时用了 providerGeneration 做判断，而这个计数在切换服务商时会自增。
   在请求飞行途中切换服务商，finally 的条件不成立，按钮就永远停在禁用状态、
   文字停在"测试中…"。现在只用请求序号判断，切换服务商也能正常恢复。

6. 连按三次空格毫无反应

   上一条还在翻译时，触发被直接丢弃，既不发请求也不提示。
   用户会以为扩展坏了。现在会显示"上一条还在翻译中，请稍候再试"。

四、性能优化

7. content script 不再对任何存储变化都重读设置

   content script 注入在每个标签页的每个 iframe 里，但只用到 5 个设置项。
   以前任何存储键变化都会触发一次全量读取，设置页保存、后台写模型缓存都会命中，
   等于把无关的写入放大成全浏览器范围的读取。现在只对真正相关的键做出反应。

8. Google 免费档不再每次翻译都写一次 session storage

   以前每成功翻译一次就写一次首选域名。正常情况域名不会变，这个写入是纯开销。
   现在只在域名真的变了的时候才写。

五、测试

· 回归测试 28 项 → 33 项，新增 5 项覆盖本次修复：
  带前缀的推理模型、非推理模型保留 temperature、错误页截断、
  content script 存储监听过滤、按钮恢复逻辑。
· review 验证脚本 4 项 → 8 项，原来的 4 个遗留项（M1 错误信息过长、
  M2 安全策略误报、M3 gpt-4o 丢失 temperature、M5 忙碌时静默丢弃）全部修复，
  遗留项清零。
· relay 冒烟测试 29 项通过；6 个 js 文件的语法检查通过。
· 版本号：3.9.5 → 3.9.6

【已知的、尚未处理的问题】
════════════════════════════════════════

以下问题本次没有改，因为改动会改变现有行为，需要先确认：

1. 目标语言是中文时，自己发出的中文消息也会被送去"翻译成中文"。

   聊天翻译默认范围是"收到与发出的消息"，而跳过逻辑在目标语言为中文时直接放行，
   原因是中文识别无法区分简体与繁体，跳过会漏掉需要简繁转换的消息。
   副作用是自己写的中文消息也会占用一次 API 调用，并显示一条几乎相同的"译文"。
   如果想避免，可以先把范围改成"仅客户发来的消息"。

2. 聊天翻译会话开启期间，每次聊天区变化都会重新扫描全部已加载消息。

   长会话（几百条消息）下会有可感知的开销。可以改成只重扫发生变化的那几条，
   属于结构改动，本次未动。
