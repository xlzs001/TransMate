1. 新增「翻译中转」方案（可选）：自己搭一个中转服务器，国内不用代理也能用免费翻译档。
2. 扩展本体功能没有变化，翻译服务、API Key、时区功能全部不受影响。

说明：中转是独立的服务端组件，不装也能正常用扩展。只有想解决"国内直连用不了免费档"时才需要部署。

一、新增：翻译中转方案（可选）

免费翻译档调用的是 Google 网页翻译接口，国内直连不到，用受限节点也经常失败。
这是网络问题，扩展本身解决不了。

中转的思路：让一台能访问 Google 的服务器替你请求，再把结果原样传回来。
因为请求是从服务器发出的，出口 IP 不在你自己的节点上，所以本地是什么网络都不影响。

· 中转代码在源码包的 relay/ 目录，是一个 Cloudflare Worker，免费额度每天 10 万次请求。
· 部署后只要在扩展的「API 地址」里填上你的中转域名即可，扩展代码一行都不用改。
· 详细步骤见 relay/README.md（含绑域名、设访问令牌、验证方法、风险说明）。

关于"任何节点都能用"这句话，需要说清楚：

· 中转能解决"访问不到 Google"的问题，前提是**中转域名本身在国内能打开**。
· Cloudflare 默认分配的 *.workers.dev 地址在国内基本不可达，所以必须绑定自己的域名。
  这是整个方案能不能落地的关键，没有域名的话中转意义不大。
· 免费额度是按天算的，个人自用完全够；如果给一批人共用，建议加访问令牌并配置限流规则。

风险提醒（重要）：

· translate_a/single 是 Google 网页端自用的非公开接口，官方随时可能改动或封禁。
  所以它只作为免费档使用，不要把收费功能建在它上面。
· 不要把中转当作商业翻译 API 转售，这涉及 Google 的服务条款。
  商用请改用官方付费接口（Google Cloud Translation / DeepL）或大模型接口。
· 中转域名不要公开传播，否则额度可能被跑光。

二、扩展本体没有变化

本次版本号提升对应的是新增的服务端组件，扩展自身代码没有功能性改动：

· 翻译服务、API Key、模型、AI 翻译专家、外观、快捷键全部保持原样。
· 时区与客户语言功能没有任何改动。
· 没有新增 host_permissions，更新后**不需要**重新授权，扩展也不会被停用。

三、如何使用中转

1. 按 relay/README.md 部署 Worker，并绑定一个自己的域名。
2. 浏览器打开 https://你的域名/health ，看到 {"ok":true,...} 说明部署成功。
3. 扩展 → 设置 → 翻译服务 → 选「Google 翻译（免费）」→ API 地址填你的域名 → 保存并允许授权。
4. 如果设置了访问令牌，地址要写成 https://你的域名/t/你的令牌 。

四、其他

· 打包脚本改为自动读取 manifest.json 里的版本号，以后升版本只需要改一处，不会再出现脚本和版本号对不上的情况。
· 回归测试的版本校验也改为从 manifest.json 读取，并检查 options.html、安装说明.txt 三处是否一致。
· 版本号：3.9.0 → 3.9.1
