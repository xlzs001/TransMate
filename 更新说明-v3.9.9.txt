TransMate 3.9.9 更新

1. 修复：新装用户的服务商默认值在三个地方不一致（设置页是"未选择"、
   内容脚本被当成"已选 Gemini"）。这个不一致不会报错，只会偶尔走错服务商，
   表现为"有时候翻译结果不太对"，很难查。现在三处已对齐。

2. 优化：语言识别、时区显示等逻辑做了重构，行为不变但更容易维护。
   实测"文字系统识别"这个函数的复杂度从 42 降到 10。

3. 内部：加入自动化检查。以后每次改代码，提交前会自动跑 6 道检查
   （静态检查 / 默认值一致性 / 回归测试 40 项 / 审查项 / 中转服务冒烟 /
   空异常说明），不合格的改动进不来。

本次不新增浏览器权限，更新后不需要重新授权，使用方式和上一版完全一样。

一、修复：服务商默认值三处不一致

  timezone.js（内容脚本）里把"用户还没选过服务商"的默认值写成了 "gemini"，
  而设置页和后台的权威定义是 ""（空字符串，表示"没选过，稍后再解析"）。

  后果：全新安装的用户，内容脚本会以为自己用的是 Gemini，
  而设置页和后台会按"没选过"的规则解析成免费档。
  两边判断不一致，但不会抛任何错误，只会在缓存指纹上体现出来，
  极难定位。现在统一成 ""，由使用处已有的兜底逻辑接管。

  这个问题是新增的"默认值一致性检查"第一次运行时自动发现的。

二、重构：把"伪装成代码的数据表"还原成数据

  timezone.js 的 detectSingleLanguage 原本是全项目最复杂的函数（复杂度 42），
  内容是 20 多个这样的分支：

      if (/[\u3040-\u30ff]/.test(text)) return makeDetectedLanguage("jpn", 1);
      if (/[\uac00-\ud7af]/.test(text)) return makeDetectedLanguage("kor", 1);
      ...

  这些分支里没有任何"决策"，只是在查一张固定的 Unicode 码位表 ——
  它本质上是数据，只是被写成了代码。

  现在改成了表 + 一个循环：

      var SCRIPT_LANGUAGES = [
        [/[\u3040-\u30ff]/, () => ["jpn", 1]],
        [/[\uac00-\ud7af]/, () => ["kor", 1]],
        ...
      ];

  效果：复杂度 42 → 10，行数 52 → 17，加一门语言从"改控制流"变成"加一行数据"。
  行为完全不变（改之前先补了 4 组测试，改完测试全绿）。

三、内部：加入自动化质量门禁

  以前所有质量把关 100% 靠人记住"要手动跑哪个命令"，没有版本控制，
  也没有 CI。现在补齐了：

  · 版本控制     项目首次纳入 git，有 .gitignore / .gitattributes
  · 一键门禁     npm run check —— 6 道检查，约 1.3 秒跑完
  · 持续集成     .github/workflows/quality-gate.yml，每次推送自动跑
  · 质量度量     npm run metrics —— AST 级统计函数长度、复杂度、重复代码

  6 道门禁分别是：
    1. 静态检查（ESLint）      拼错变量、恒真恒假、Promise 返回值写错
    2. 默认值一致性            5 份 DEFAULTS 副本漂移（本次抓到真问题）
    3. 回归测试（40 项）       已修过的 bug 重新出现
    4. 审查项（8 项）          版本号、HTML id、开关默认值不一致
    5. 中转服务冒烟（29 项）   中转服务的请求/响应契约被改坏
    6. 空 catch 有说明         吞掉异常却不写为什么

四、内部：给"吞掉异常"的地方补上说明

  全项目有 12 处空的 catch 块。空 catch 本身不一定是错的
  （很多地方确实"失败了也无所谓"），问题是没写清楚为什么无所谓 ——
  半年后接手的人不敢删也不敢改。现在 12 处全部补上理由，
  并加进门禁：以后新写的空 catch 不写说明会被拦下。

  · docs/工程规范手册.md      写代码前先看，所有规则带真实行号
  · docs/代码质量基线报告.md  当前代码的量化状况，以及该先动哪里
  · docs/学习路线图.md        12 周能力提升计划，练习题用本项目函数
