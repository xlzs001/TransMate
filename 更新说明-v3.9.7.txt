TransMate 3.9.7 更新

本次是两个新功能，都围绕"聊客户"这件事，一个防事故，一个提回复率：

1. 新增：翻译后的"硬信息"自动核对。译文里如果数字、型号、贸易术语（FOB/CIF 这类）、
   柜型（20GP/40HQ）或货币单位与原文对不上，会直接标出来提醒你核对。
   大模型偶尔会把 40HQ 写成 40GP、CIF 写成 CFR，人眼扫一遍基本发现不了，
   外贸里错一位就是事故。这项核对完全在本机做，不增加任何 API 调用和费用。

2. 新增：客户沟通时间建议。除了显示客户当地时间，还会按客户当地的工作时段
   判断"现在发过去合不合适"：不在工作时段会在标签上亮起一个小橙点，
   点开能看到"距客户上班还有约 X 小时"。
   上班/下班时间可以自己改，周末办公的地区可以勾选"周末也算工作日"。

本次不新增浏览器权限，更新后不需要重新授权。

一、硬信息一致性校验

1. 为什么做这个

   大模型翻译时偶尔会"顺手"改写不该变的东西。这类错误有两个特点：
   一是人眼几乎发现不了（40HQ 和 40GP 只差一个字母），
   二是后果很严重（柜型报错、贸易术语报错都是真金白银）。
   所以这里只做高置信、低误报的检查，命中一律表述为"请核对"，不做任何自动修改。

2. 核对哪些内容

   · 数字：千分位、小数补零、前导零都视为同一个数。
     "1,200" 与 "1200" 一致，"12.50" 与 "12.5" 一致，不会因为这些写法差异误报。
   · 贸易术语：EXW / FCA / FAS / FOB / CFR / CIF / CPT / CIP / DAP / DPU / DDP。
   · 柜型：20GP / 40HQ / 40HC / 45HQ 等。HC 与 HQ 是同一规格，统一成 HQ 比对，
     中文的"40 尺高柜"也归一到 40HQ，不会因为换了写法就误报。
   · 货币：RMB 归到 CNY，"美元/美金/美刀/USD/$"都归到 USD，
     避免同一种货币的四种写法互相误报。
   · 型号：字母在前、数字在后，例如 HR-2400、ABC1234。
     同时排除了 USD12、FOB1000 这类"金额/术语 + 数字"的误判。

3. 怎么提示

   · 网页表单翻译：在提示条里逐行列出，例如"请核对：原文的数字 500 没有出现在译文里"。
   · WhatsApp 聊天窗口：提示直接挂在译文下面，用橙色左边框标出，一眼能看出是哪条消息。
   · 单条消息最多报 6 条，避免长文本刷屏把真正重要的一条淹掉。

4. 可靠性

   校验本身如果出任何异常，一律静默返回"无提示"——绝不因为校验失败而让翻译本身失败。
   原文里出现中文数字时（"三千套"），只报"数字丢失"，不报"多出数字"，
   因为中文数字本来就无法与阿拉伯数字一一对应，否则全是误报。

二、客户沟通时间建议

1. 为什么做这个

   只显示"客户当地时间"其实还不够——业务员真正需要判断的是"现在发过去合不合适"。
   凌晨三点发过去的报价，客户第二天早上看到时已经被埋在消息列表里了。

2. 怎么工作

   · 按客户当地时间判断是否处于工作时段，默认 09:00–18:00。
   · 处于工作时段：标签上不显示任何东西，弹层里写"可以直接发送"。
   · 不在工作时段：标签上亮起一个小橙点（鼠标悬停即可看到完整文案），
     弹层里写明"距客户上班还有约 X 小时 Y 分"。
   · 跨周末会自动跳过：周五晚上给出的是"距下周一上班"的时间，不会算成周六。

3. 可以自己调

   设置页「客户地区与当地时间」里新增：

   · 提示客户沟通时间（开关，默认打开）
   · 上班时间 / 下班时间（默认 9 点和 18 点）
   · 客户周末也算工作日（默认关闭，中东等周末办公的地区可勾选）

   上班时间填得比下班时间晚时会自动纠正，不会出现空时段。

三、测试

· 回归测试 33 项 → 35 项，新增 2 项：
  硬信息校验（数字/术语/柜型/货币/型号的归一与误报防护，以及每个翻译出口都真的调用了校验）、
  沟通时间（跨日/跨周末计算、上班时间填反的自愈、开关与无时区时的清空行为、
  以及计算逻辑确实接到了渲染路径上，不是死代码）。
· review 验证脚本 8 项通过，遗留项保持清零。
· 7 个 js 文件的语法检查通过。

【已知的、尚未处理的问题】
════════════════════════════════════════

以下问题本次没有改，因为改动会改变现有行为，需要先确认：

1. 目标语言是中文时，自己发出的中文消息也会被送去"翻译成中文"。

   聊天翻译默认范围是"收到与发出的消息"，而跳过逻辑在目标语言为中文时直接放行，
   原因是中文识别无法区分简体与繁体，跳过会漏掉需要简繁转换的消息。
   副作用是自己写的中文消息也会占用一次 API 调用，并显示一条几乎相同的"译文"。
   如果想避免，可以先把范围改成"仅客户发来的消息"。

2. 聊天翻译会话开启期间，每次聊天区变化都会重新扫描全部已加载消息。

   长会话（几百条消息）下会有可感知的开销。可以改成只重扫发生变化的那几条，
   属于结构改动，本次未动。

3. 长输入没有预检。

   超长文本会先发出去、被服务商拒绝，再走分片重试。可以先按字符数预判，
   省掉一次注定失败的请求。

4. 推理模型的 token 预算里包含推理 token。

   预算按"可见输出"估算，但 GPT-5 / o 系列会先花掉一部分 token 用于推理，
   极端情况下可能因为预算不够而被截断。需要按模型类型分别估算。
