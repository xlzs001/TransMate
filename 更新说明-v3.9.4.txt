一、WhatsApp 聊天窗口翻译改为常开

以前的做法是：先打开开关（那时叫"允许快捷键"），再按 Alt+Q 才会开始翻译。
也就是说开关只是"允许"，真正的触发靠快捷键。

现在改成：开关打开后进入聊天窗口就自动翻译，不需要任何额外操作。

· 开关按钮保留在原来的位置，只是文案改成了「聊天翻译常开」。
· 快捷键没有删掉，仍然可以用：按一次临时关闭译文（只看原文），再按一次恢复。
· 手动关闭后不会被自动重新打开，直到你重新按快捷键、或者去设置页把开关重新切换一次。

开关默认是打开的。这意味着：

· 新装用户：装好后打开 WhatsApp 就会自动翻译。
· 已有用户：如果你的设置里没有存过这个开关，升级后也会变成打开状态。

如果你不想要自动翻译，去 设置 → WhatsApp 聊天窗口翻译，把右上角的开关关掉即可。

二、修复：Azure OpenAI 完全无法使用

这是个一直存在的严重问题，现在才被发现。

Azure OpenAI 的模型名不是填在请求里的，而是写在 API 地址的 deployment 段中，例如：

  https://你的资源.openai.azure.com/openai/deployments/gpt-4o/chat/completions?api-version=...

所以扩展的请求体里本来就不包含模型名。但校验逻辑却把 Azure 当成"需要模型名"的服务，
结果就是你填好地址和 Key、点保存或测试，得到的是"请填写 Azure OpenAI 的模型名称"，
而那个模型输入框填什么都不会生效。

现在已修正：Azure 不再要求填写模型名，模型输入框会直接显示"该服务不需要模型名称"。

三、修复：Azure 上部署 GPT-5 / o 系列模型会报错

Azure 上如果部署的是 GPT-5 或 o1/o3/o4 系列，这些模型不认 max_tokens 和 temperature 参数，
发了会直接返回 400。

以前的代码对所有 Azure 部署都发 max_tokens，所以只有部署旧模型时能正常工作。
现在会根据地址里的 deployment 名字自动判断，GPT-5 / o 系列改用 max_completion_tokens，
其余模型保持原样。

四、其他

· 设置页的开关文案从「允许快捷键」改为「聊天翻译常开」，快捷键下方的说明同步更新为
  "开关打开后进入聊天窗口会自动翻译，不需要按快捷键"。
· 安装说明里"内置聊天窗口翻译"一节同步更新。
· 「智谱 GLM（自选模型）」的帮助文字原本写"只想用免费模型请选上一项"，但它的上一项并不是免费档，
  已改为直接写明选项名称。
· 回归测试从 25 项增加到 28 项，新增三条：
  Azure 不填模型名也能正常工作；Azure 上部署 GPT-5 时使用正确的参数；
  聊天翻译默认开启且不依赖快捷键。
